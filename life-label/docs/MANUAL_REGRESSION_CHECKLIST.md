# 手动回归清单（MANUAL_REGRESSION_CHECKLIST）

> 每次重构后按本清单逐项手动验证，确认**行为与重构前一致**。
> 运行：`npm run dev` → 浏览器打开 dev 地址（重构前为 `node .claude/static-server.js` → `localhost:8777`）。
> 勾选规则：行为与 `REFACTOR_BASELINE.md` 描述一致才算通过；任何差异需记录。

---

## A. 启动与加载
- [ ] 打开页面先显示红底"人生标签交易所"加载画面。
- [ ] 字体加载完成后自动进入**标题页**（标宝 cheer 表情、"人生标签交易所 / 试用期" / 副标题 / "开始上工"按钮 / 版本号）。
- [ ] 控制台无报错（数据加载成功、校验通过）。
- [ ] 7 个 JSON 全部从 `data/` 成功加载（Network 面板 200）。

## B. 新局 / 进班
- [ ] 点"开始上工" → 进入**第一班班前页**（SHIFT_START）。
- [ ] 班前页显示：班次名、introText、本班目标、调查机会数、到期回单数、规则文案（block_end → "须处理完所有案件方可收班"）。
- [ ] 状态栏：第 1 班、押金 5/5（5 个红色押金图标全亮）、LED 行情滚动、标宝 logo。
- [ ] 点"开始处理" → 进入工作台（SHIFT_ACTIVE），左侧来货堆显示待处理案件，标宝气泡出现一次。

## C. 选案件 / 扒底 / 揭标
- [ ] 点来货堆顶卡 → 案件卡从来货区滑入工作台中心（slide 动画）。
- [ ] 卡底三个 tab：扒底 / 揭标(带剩余数 badge) / 退货。
- [ ] 点"扒底" → 调查机会 −1，卡翻面显示底细（backgroundText），ACTION_RESULT 反馈条；已扒底后该 tab 变"翻面"，可正反翻转。
- [ ] 点"揭标" → 调查机会 −1，按 order 揭一枚底标，正面对应"?"变为已揭标签（弹出动画），ACTION_RESULT 反馈。
- [ ] 调查机会为 0 时，扒底/揭标 tab 置灰不可点。

## D. 出货
- [ ] 拖动案件卡到某个**可用流向柜台**（高亮）→ 松手 → 出货盖章动画 → 即时反馈（ACTION_RESULT，immediateText）。
- [ ] 拖到**不接收该案件 / 未就位**的柜台 → toast 提示原因，卡滑回中心（不出货）。
- [ ] 出货后案件移出来货堆，跟单板出现该案件条目（流向色 + pendingText）。
- [ ] 若该流向 callbackDelay=0 → 关闭反馈后立即进入 CALLBACK_REVIEW。

## E. 退货
- [ ] 点卡底"退货" tab，或拖卡到左下**退货箱**（高亮）→ 退货动画（卡缩小飞入退货箱）。
- [ ] 退货反馈（immediateText），案件移出来货堆。
- [ ] 退货带 depositDelta 时押金相应变化（见 J）。

## F. 即时反馈（ACTION_RESULT）
- [ ] 扒底/揭标/出货/退货后出现底部反馈条，标题随操作类型变化。
- [ ] 点"按任意键继续"或按任意键或点击任意处 → 关闭，回到正确的下一相位。

## G. 延迟回单（跟单板 + CALLBACK_REVIEW）
- [ ] 出货后回单进入 `pendingCallbacks`，跟单板显示"跟单中..."。
- [ ] 到期班次（dueShiftOrder==当前班 order）进班时回单变"⚡回单已达"，班前进入 CALLBACK_REVIEW 逐条确认。
- [ ] 回单页显示：案件→流向、callbackText、（如有）长期回响、结果（成立/失误/...）、押金增减。
- [ ] 点"确认回单" → 逐条处理，队列清空后回 SHIFT_ACTIVE（或继续流程）。

## H. 押金扣除 / 增加
- [ ] 押金减少时：状态栏押金图标对应熄灭，红色 delta 数字上浮动画，押金图标闪烁。
- [ ] 押金增加（成功回单 depositDelta>0）时数值上调，但不超过 max(5)。
- [ ] 押金剩 2 枚时，标宝气泡自动出现一次提示。

## I. tendency 增加（倾向）
- [ ] 出货带 tendencyDeltas 的流向 → 对应倾向累加（可经结局/失败页主导倾向间接验证）。
- [ ] 退货带 tendencyDeltas → 对应倾向累加。
- [ ] 仅出货/退货影响 tendency；扒底/揭标/选案件不影响。
- [ ] （进阶）某倾向累到 ≥3 成为主导，结局/失败页反映该主导倾向（见 N、P）。

## J. 班次结束 / 绩效 / 结算（SHIFT_SUMMARY）
- [ ] 处理完所有案件自动收班；或点"收班"：block_end 班有剩余则拒绝（toast），auto_return 班弹确认框→确认后剩余案件自动退货。
- [ ] 结算页显示：出货数 / 手动退货 / 自动退货 / 剩余押金、班次绩效（达标✓/未达标✕及文案）、标宝附注。
- [ ] 绩效未达标按规则扣押金，且扣罚次数不超过 performancePenaltyCap。
- [ ] 点按钮 → 有下一班进入下一班前页；第 7 班后进入终审/结局。

## K. 限时班（班 3–7）
- [ ] 限时班班前页显示红色限时警示块（时长 + 超时说明）。
- [ ] 进入 SHIFT_ACTIVE 后状态栏计时器开始倒数。
- [ ] ≤60s 计时器变金色 + "!"，≤30s 变红并闪烁。
- [ ] 计时器在弹窗/回单/结算相位暂停，回工作台继续。

## L. 限时结束（强制收班）
- [ ] 计时器归零 → 强制收班 toast，未处理案件自动退货，进入 SHIFT_SUMMARY。
- [ ] 结算页顶部显示"限时归零·系统强制收班"横幅与自动退货数。
- [ ] 绩效照常结算。

## M. 多班推进
- [ ] 连续推进 7 班，每班案件/流向/规则与 shifts.json 一致（流向逐班增多）。
- [ ] 跨班回单按到期班正确触发。

## N. 正常结局（ENDING_DISPLAY）
- [ ] 第 7 班收班 → 终审清算剩余回单（若有）→ 结局报告页。
- [ ] 报告显示：reportHeader、title、bodyText、统计行（押金/班次/案件/失误/绩效扣罚）、主导倾向、档案标签。
- [ ] 结局与押金/班次/失误/tendency 条件匹配（如高押金+7班+低失误→卓越；某倾向≥阈值→对应倾向结局）。
- [ ] 点"再来一次" → 回到新局（startRun，第一班班前页）。

## O. 失败结局（RUN_FAILED）
- [ ] 押金归零（任意时点：退货/回单/绩效/自动退货）→ 立即进入失败页，中断当前流程。
- [ ] 失败页显示：归零通知头、档案摘要（失败班次/已完成班数）、可见标签、初步底标、建议流向、标宝附注、统计。

## P. 失败页动态内容（按主导倾向）
- [ ] 主导倾向（≥3）不同 → 失败页"初步底标"末条与"建议流向"对应 `TENDENCY_FAILURE_INFO`。
- [ ] 无主导倾向 → 显示 `_none`（操作风格未分化）文案。

## Q. 重开
- [ ] 失败页"重新报到" / 结局页"再来一次" → 完全重置为新局（押金 5/5、第 1 班、无回单、tendency 归零）。
- [ ] 重开后再次走完整流程无残留状态。

## R. 通用
- [ ] 窗口缩放：游戏按 1280×720 基准等比适配，交互坐标正确。
- [ ] 全程控制台无新增错误/警告。
- [ ] 视觉（颜色、字体、布局、动画）与重构前一致。
